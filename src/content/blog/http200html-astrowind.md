Clash 更新订阅后若得到的是网页，问题通常不在「有没有收到 HTTP 回答」，而在「回答里的资源是不是配置」。MDN 说明：状态码表示某次请求是否已成功完成；成功响应是 200–299。对 GET，200 表示资源已取出并放进消息正文。服务器完全可以把登录页、站点说明或错误说明当作该 URI 的资源，于是你看到网页，状态码却仍可能是 200。识别时要把状态码、重定向和「有没有正文」合在一起看，而不能只看客户端有没有下载到文件。

## 适用条件

适用于订阅 URL 已返回完整 HTTP 响应，且正文看起来像网页、门户页或说明页的情况。适用于最终码为 200 但内容无法当配置使用，或最终码为 4xx、5xx 却仍带有可打开页面的情况。没有状态码的连接失败，以及仍停留在 1xx 中间响应，都不按「返回网页」处理。

## 识别步骤与判断依据

1. 记录最终状态码所属类别。2xx 只说明请求按 HTTP 定义成功完成；4xx 是客户端错误；5xx 是服务器无法妥善处理。401 语义为未认证，必须先认证才能拿到所请求响应，伴随的页面不能当配置。403 表示身份已知但拒绝给出资源。404 表示找不到资源，在浏览器中意味着 URL 不被识别，网页场景里极为常见。410 表示内容已永久删除且无转发地址。503 用于维护或过载等临时情况，并提到应发送说明问题的页面。这些页面能打开，也不等于有效配置。
2. 检查 300–399 重定向。301、308 是永久改 URI；302、307 是临时改 URI，307 与 308 还要求保持原方法；303 要求用 GET 去另一 URI 取资源。跟随跳转后的 200 正文属于新 URI。若新 URI 是登录或站点入口，判断依据就是「当前正文不是原订阅资源」。
3. 对最终 200 仍要区分「请求成功」和「正文可用」。204 没有可发送的正文，不可能是配置。206 是范围请求的部分内容，不能当完整配置。203 表示元数据可能来自本地或第三方副本而非源站。只有在最终为 200、未经指向网页的跳转、且正文是该订阅 URI 所代表的资源时，才具备「像配置」的 HTTP 前提。
4. 综合判断：出现 401、403、404、410、503 等并带页面，或 3xx 后落到网页的 200，或 204、206，即可认定当前响应不是有效配置。不要用「文件能保存到本地」代替上述判断。

## 失败时下一步

无法看到状态码时，先确认请求是否完成。最终 401、407、511 先处理认证（407 针对代理，511 针对网络准入）。最终 404、410 应更换或停用该地址，不要保存错误页。最终 200 且无跳转仍是网页时，向订阅提供者确认该 URI 是否直接提供配置正文，确认前不要覆盖已有配置。若收到未列出的状态码，按非标准响应原样记录数字，再结合是否有正文判断，不要强行当作 200 配置。
