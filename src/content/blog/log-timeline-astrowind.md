要把 Clash 错误按时间整理成记录，依据是全局配置里的日志级别，以及官方写明的输出位置：内核日志只在控制台和控制页面出现。整理前先分清“错误”和“一般运行内容”，再按你动手操作的时刻截取对应输出，而不是把某一时段里看到的所有行都当成故障年表。

## 适用条件与级别取舍

适用场景是：已经能复现问题，需要把“出错时刻”和“错误本身”一一对应后存档，供以后对照。不适用的情况是：当前为 `silent`（静默，不输出），或级别停在 `debug`/`info` 却仍把全部行当作错误。

官方对级别的划分如下，这是筛行的判断依据：

- `silent`：不输出，无法整理。
- `error`：仅输出发生错误至无法使用的日志。
- `warning`：输出发生错误但不影响运行的日志，以及 error 级别内容。
- `info`：输出一般运行的内容，以及 error 和 warning 级别的日志。
- `debug`：尽可能输出运行中所有的信息。

若记录目标是“已经无法继续使用”，只保留可归入 error 的内容；若还要保留“出错但内核仍能运行”，才纳入 warning。`info` 与 `debug` 会混入一般运行内容，不能直接当作错误年表。配置项为 `log-level`，例如写成 `error` 或 `warning`。

## 按时间整理的操作步骤

第一步，复现前记下操作开始的本地时分秒，并确认 `log-level` 不是 `silent`。若当前是 `debug` 或 `info`，先改为 `error` 或 `warning`，缩小同一时段里与错误无关的行。

第二步，只做一次与故障相关的操作，暂停其他会触发代理、解析或策略变化的动作，让该时间窗尽量对应这一次操作。日志只出现在控制台和控制页面，两处都要看，不要只盯一处。

第三步，从记下的开始时刻向后阅读输出。按官方含义筛行：能归入“错误至无法使用”的留下并标注时刻；属于一般运行的丢弃。同一时刻若同时出现可归入 warning 与 error 的内容，按级别分开记录，不要合并成一条。

第四步，将筛出的行按时间先后写成记录。每条至少包含：时刻、级别归属（error 或 warning）、原文要点。未在该时间窗出现的内容不要补写进去。需要对照“不影响运行的错误”时，用 `warning` 再复现一次，另表存放，避免和 error 混在同一列。

## 失败时下一步

时间窗内完全没有输出：先查是否误设为 `silent`；再确认是否漏看了控制页面或控制台（官方写明这两处输出）。

输出极多、无法按时刻对齐：把 `log-level` 从 `debug` 或 `info` 降到 `error` 后只复现一次。仍过多则只提取明确属于 error 的行，warning 另存，避免一张表里级别混杂。

有输出但无法判断是否“无法使用”：回到级别定义，禁止把 info 的一般运行内容标成错误。仍无法取舍时，保持 `log-level: error` 再复现，以“仅无法使用类错误才会出现”作为写入记录的依据。
