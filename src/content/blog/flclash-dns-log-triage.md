FlClash v0.8.99 的发行说明新增 DNS 查询日志，并修复了某些网络报告“没有 DNS 服务器”时的解析失败。日志提供了新的观察入口，但“有 DNS 记录”和“网页可以访问”仍是两件事。以下是基于发行记录与 mihomo DNS 文档的排查建议，没有在具体设备上亲测。

## 一次复现只观察一个目标

先记下客户端版本、网络类型和失败时间，固定一个打不开的网站，打开当前版本提供的 DNS 查询记录视图。重新发起访问，然后对照相同时间段的连接记录。不同屏幕和版本的入口可能不同，找不到视图时先确认确为 v0.8.99，不要按另一客户端的按钮名称操作。

关注目标域名是否出现、是否拿到结果，以及随后是否发生连接。缓存可能让新请求没有再次发起查询，因此一次未见记录不足以认定 DNS 完全没接管。可重启目标应用或按客户端支持的方式清理缓存后再观察，避免同时改掉整套 DNS。

## 三种结果对应不同下一步

没有目标查询：检查应用是否使用自己的加密 DNS、是否绕过当前代理接管，以及观察时间窗口是否正确。有查询但解析失败：核对生效 DNS 配置、解析服务器是否可达和节点域名解析是否陷入依赖循环。查询成功但连接超时：接着看路由、节点和目标连接，不要继续反复替换 DNS 地址。

使用 fake-ip 时，结果可能是映射地址，不能因为它不是网站公网 IP 就判为污染。mihomo 文档对 `fake-ip` 与 `redir-host` 有不同定义；先确认当前模式，再解释结果。

## 新版本修复不能代替现场判断

发行说明提到“网络未报告 DNS 服务器”这一修复，仅能说明项目修改了该情形的处理。升级后仍失败时，保存自己的错误类别和最小复现，不能推断所有 DNS 问题已经解决，更不能用这条修复证明某个网络一定可用。
