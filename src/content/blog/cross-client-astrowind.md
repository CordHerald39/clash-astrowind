换电脑端客户端之前，应先把本机环境、安装形态、内核与图形层能力、以及发布说明里已写明的限制写成清单。不能因为都能读取相近的配置文本，就假定系统代理、TUN、服务进程或覆写逻辑可以原样带走。下列步骤只依据 Clash Verge Rev 仓库说明和发布说明，用来列出兼容性问题。

## 适用条件

适用于计划在 Windows、macOS 或 Linux 桌面更换 Clash 图形客户端，或从某一 Verge Rev 版本换到另一版本之前的评估。仓库将其定义为基于 Tauri 的 Clash Meta GUI，内置 Clash.Meta（mihomo）内核，并支持切换 Alpha 版本内核。安装包需按系统从发布页选择。Windows 发布说明写明不再支持 Win7；仓库写明支持 Windows（x64/x86）、Linux（x64/arm64）和 macOS 11+（Intel 与 Apple）。若当前系统落在该范围之外，应把操作系统不受支持列为第一项，而不是继续比较节点字段。

## 列出兼容性项的操作

第一步，记录操作系统、CPU 架构和发行通道。仓库把版本分成 Stable（正式版，适合日常使用）、已废弃的 Alpha，以及 AutoBuild（滚动更新，可能存在缺陷）。清单里要写清当前属于哪一类、目标属于哪一类，避免把测试通道的行为当成正式版契约。

第二步，记录安装包形态。Windows 区分正常版本和内置 Webview2 版；后者体积较大，仅在企业版系统或无法安装 Webview2 时使用。Linux 还区分 deb 与 rpm 的安装方式。若目标环境禁止安装 Webview2，或 CPU 是 ARM64 而不是 x64，必须把包类型和架构不一致列为硬性不兼容。

第三步，列出图形层能力是否被目标客户端声明。仓库 Features 包括配置文件管理和增强（Merge 与 Script）、系统代理和守卫、TUN、可视化节点和规则编辑、WebDav 配置备份和同步、自定义主题与 CSS Injection、内核 Alpha 切换。这些不是内核 YAML 的必选项。旧客户端若依赖其中某一项，而目标客户端没有对等声明，应记为功能缺口。

第四步，把最近发布说明中的平台限制抄成检查表。v2.5.7 涉及订阅包含自定义 DNS 时 DNS 覆写在重启后被关闭、Windows 系统盘删除权限误判导致服务模式和 TUN 不可用、安装服务提示 program not found、macOS 内核启动失败与系统代理读取失败、服务模式停止时强制结束内核。v2.5.6 涉及代理集合与规则集合更新误报、未安装服务时普通权限下内核无法启动、系统隔离权限、旧版服务残留、用户目录在外置磁盘。v2.5.5 涉及不同来源订阅或规则集共用缓存路径导致服务模式无法启动、DNS 覆写被 Merge 或 Script 覆盖、管理员启动后数据目录所有权不符、Linux 安装服务后仍无法开启 TUN。当前环境只要用到服务模式、TUN、DNS 覆写、Merge 或规则集合，对应条目就要进入清单。

第五步，把客户端状态和内核语法分开。DNS 覆写按订阅独立记忆、扩展配置与脚本的执行顺序、服务模式与 Sidecar、升级后服务版本或协议不兼容，都属于封装层。这些状态不会随一份配置文本自动迁移，必须单独列出。若需要对照订阅地址，只保留已有链接中的 `token=示例` 这类参数片段，不要写入额外完整网址。

## 判断依据

一项内容只有在同时满足「当前正在使用」和「目标环境的系统范围、安装包、服务或 Sidecar、发布说明中的限制会改变结果」时，才应记为兼容性问题。Win7、Webview2 缺失、服务权限、外置磁盘上的用户目录、共用缓存路径，都是发布说明直接写过的条件，判断时以这些原文为准，不补充未出现的菜单名称。

## 失败时下一步

若清单列完仍无法判断能否更换，应停止切换，回到同一仓库发布页，核对本系统分段里相关缺陷是否仍未修复，并确认目标包架构与本机一致。Windows 服务安全检查未通过时，较新版本会说明原因；若只有笼统失败信息，先把服务能否安装、能否在 Sidecar 下启动内核这两项补进清单，再决定是否继续更换客户端。
