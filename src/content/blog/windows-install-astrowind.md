首次在 Windows 上安装 Clash 电脑端（以官方仓库发布的 Clash Verge Rev 为准），安装前要准备的是能对上发布说明的事实，而不是「先下一份再看能不能开」。缺系统版本、处理器架构、WebView2 能否使用、发行通道与准确文件名，就会下错包，或装完界面起不来、服务模式与 TUN 不可用。

## 系统和架构：两条硬条件

发布页写明 Windows 不再支持 Win7。安装前先确认当前系统版本：仍是 Win7 则不在官方支持范围内，应先升级系统，而不是继续运行安装包。仓库说明支持 Windows（x64/x86）；同一 Release 里 Windows 安装包分成「64位(常用)」与「ARM64(不常用)」。安装前必须知道本机是常见的 x64，还是较少见的 ARM64。架构与文件名必须一致，不能把 x64 与 ARM64 互换，更不能下载 macOS 的 dmg 或 Linux 的 deb/rpm。

判断依据：系统信息中的系统类型。x64 对应 `Clash.Verge_*_x64-setup.exe`；确认 ARM64 才选 `*_arm64-setup.exe`。版本号以你选定的 tag 为准（例如某一正式版的 `Clash.Verge_2.5.7_x64-setup.exe`），不要混用不同 tag 的安装程序。

## 发行通道与 WebView2：决定下哪一个文件

仓库把发行版分为正式版 Stable（高可靠性，适合日常使用）和滚动更新 AutoBuild（适合测试反馈，可能存在缺陷）。首次安装、日常使用应准备 Stable 的安装包，到 Release 页按当前 tag 下载，而不是 Autobuild。Alpha 通道已标为废弃，不要当作安装来源。

同一架构还有两类 Windows 包，选择前要准备「本机能否安装或使用 WebView2」这一信息：

- 正常版本（推荐）：依赖系统侧的 WebView2。
- 内置 WebView2 版：体积较大，发布说明写明仅在企业版系统或无法安装 WebView2 时使用。

普通可自行安装运行库的环境，按说明选正常版本；策略锁定、企业镜像无法安装 WebView2 时，再准备同架构的 `*_fixed_webview2-setup.exe`。不要因为文件更大就默认下内置版。下载只认官方 Release 上的完整文件名；部分资源旁的 `.sig` 是签名文件，不是安装程序。

## 权限与旧环境，以及对不上时的下一步

若计划使用服务模式或 TUN（虚拟网卡），安装前还应弄清：本机是否已有旧版服务残留、安装或修复服务时能否提供管理员授权、是否会先用管理员账户启动再切回普通用户。近期版本曾处理系统盘根目录删除权限被误判、系统隔离权限被误判、安装服务提示「program not found」、未安装服务时普通权限无法启动内核、旧版服务状态残留无法重装、首次以管理员启动导致数据目录所有权不符、服务因路径或目录权限无法启动等情况。这些不是安装包里的可选项，而是安装前就该记录的环境事实。仓库还指向文档页与 Windows 常见问题，可在安装前打开备用。

对不上或失败时：仍是 Win7 → 先升级，不要强装。架构或文件名不符 → 删除错误文件，回到同一 Release 改下对应资源。界面无法出现且环境无法安装 WebView2 → 改用同架构内置 WebView2 包，而不是反复重装正常版。服务安装失败、提示 program not found、权限或残留 → 按该版本给出的原因说明与修复文档链接处理，并避免管理员与普通用户混用数据目录。来源不明或找不到对应文件 → 只使用仓库给出的 Release 页。AutoBuild 出现缺陷 → 改回 Stable。

把「系统版本、架构、WebView2、Stable 文件名、是否有旧服务」写清之后，安装只是执行已选好的那一个官方安装包。
