在家庭网络和办公网络之间切换时，同一份配置表现不同，往往是出站网卡、绑定地址、局域网许可和 IPv6 随网段变化，而不是文件丢失。记录配置的目的，是在两套网络里留下可对比的全局字段快照，便于以后按同一顺序核对，而不是凭印象描述某一地点能用、另一地点不能用。

## 适用条件

适用于能编辑全局配置、并且会在家庭与办公等不同网段间切换的环境。切换前先确认 mode 仍是预期值：rule、global 或 direct。global 还依赖 GLOBAL 策略组的选择。若 profile.store-selected 为 true，API 对策略组的选择会被储存并在下次启动时使用，切换网络后看到的同一配置可能已带上旧选择，记录时必须写明该项。store-fake-ip 会保存 fakeip 映射表，域名再次发生连接时使用原有映射地址；跨网段时旧映射可能不再合适，应一并记录。

## 切换时按网卡与局域网字段做快照

每次连接到家庭或办公网络后，按同一顺序记录下列字段。

其一，interface-name，即流量出站接口。两地默认网卡名通常不同，未指定时内核选用的接口也可能不同。应记录当时系统中的接口名。其二，allow-lan 与 bind-address。allow-lan 为 true 时，其他设备可经代理端口访问互联网；bind-address 为星号表示绑定所有 IP，也可绑定单个 IPv4 或单个 IPv6。办公网地址变化后若仍绑定旧地址，局域网侧会连不上，快照里要写下当前绑定值。其三，lan-allowed-ips 与 lan-disallowed-ips。允许段默认 0.0.0.0/0 和 ::/0，禁止段默认空，且黑名单优先。办公网某地址若落入禁止列表，必须在记录中标出。其四，ipv6 是否允许内核接受 IPv6 流量，默认 true。家庭与办公只要有一方没有 IPv6 路由，同一配置的连接路径就不同。其五，Linux 环境记录 routing-mark。若启用用户验证，记录 authentication 与 skip-auth-prefixes（文档示例包括 127.0.0.1/8 与 ::1/128）。

判断依据：两套快照里仅 interface-name 或 bind-address 不同，而 mode 与策略储存项相同，应优先把差异归到接口与绑定；若 allow-lan 与地址段在办公网不匹配，应先核对地址段再谈规则文件。

## 记录失败或对不上时的下一步

将 log-level 调到 info 或 debug，在两种网络各保存一段控制台或控制页面日志，核对是否出现接口不可用或绑定失败一类信息。silent 完全不输出，error 只留下无法使用的错误，都不适合做切换对照。tcp-concurrent 会对解析得到的全部 IP 发起连接并取第一个成功者，双栈与单栈网络结果不同，快照应包含该开关。find-process-mode 在路由器上推荐 off，电脑端默认 strict；若家庭走旁路设备、办公走本机，进程匹配也会不同，需写入记录。不要只保存一个配置文件名。没有接口名、绑定地址和 mode 的记录，无法在两种网络之间对照。外部控制器若从回环改为监听所有 IP，也应记入，以免把 API 访问算进网络差异。
